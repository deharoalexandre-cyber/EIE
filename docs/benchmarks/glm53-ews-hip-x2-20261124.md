# GLM-5.3-Flash with EWS on AMD Ryzen AI MAX+ 395

**Experimental measurement, 24 November 2026. One measured request per profile.**

## Scope

EIE served the frozen six-shard GLM-5.3-Flash UD-Q4_K_XL artifact (199,707,321,347 bytes) on a GMKtec EVO-X2 with a Radeon 8060S (`gfx1151`) and 128 GiB installed unified memory. All six model shards were checked by size and SHA-256 on the X2. EIE used HIP SDK 7.2, the experimental Unsloth GLM runtime and the EWS patch. This was an isolated EIE HTTP test; Elyne GRCA and its six sessions were stopped, and no Next application loop was involved.

The server log records `offloaded 47/47 layers to GPU` for the full-placement profiles. This **does not** mean that all 199.7 GB of model weights remained on the GPU: EWS kept a bounded expert cache and read selected expert slabs during inference. `/v1/admin/ews/status` reported zero host expert-cache bytes for those profiles. The largest measured cache bound was 82,434,850,816 device bytes, close to the practical GPU memory limit on this machine.

## Measured HTTP results

After a two-token arithmetic warm-up, the same short French prompt requested a numbered list of thirty office-organization tips. Requests used `temperature: 0`, `stream: true`, `one_shot: true`, `enable_thinking: false` and a 128-token cap. Each response emitted 128 content fragments for 128 completion tokens, with `finish_reason: length`; the answer was therefore partial. Decode cadence is `(128 - 1) / (last content timestamp - first content timestamp)`. HTTP wall time includes prompt evaluation and response delivery. All profiles ran sequentially.

| Placement | EWS slots | Device expert cache | First content | Decode cadence | HTTP wall | EWS bytes read, warm-up + measured |
|---|---:|---:|---:|---:|---:|---:|
| Hybrid, `gpu_layers: 20`, graphs disabled | 8 | 2.20 GB (2.95 GB host) | 86.397 s | 0.655 tokens/s | 281.788 s | 714.85 GB |
| `gpu_layers: 47` | 8 | 5.15 GB | 84.326 s | 0.659 tokens/s | 278.663 s | 722.89 GB |
| `gpu_layers: 47` | 16 | 10.30 GB | 71.393 s | 0.781 tokens/s | 235.465 s | 598.97 GB |
| `gpu_layers: 47` | 32 | 20.61 GB | 56.743 s | 0.956 tokens/s | 190.778 s | 474.76 GB |
| `gpu_layers: 47` | 64 | 41.22 GB | 43.086 s | 1.276 tokens/s | 143.579 s | 347.22 GB |
| `gpu_layers: 47` | 96 | 61.83 GB | 32.062 s | 1.642 tokens/s | 110.178 s | 254.30 GB |
| `gpu_layers: 47` | 128 | 82.43 GB | 26.279 s | **2.103 tokens/s** | 87.103 s | 196.88 GB |

Within this one-prompt sequence, 128 versus 8 device slots gave **3.19 times** the decode cadence and **72.8% fewer** EWS reader bytes. All six full-placement profiles produced the same 128-token response SHA-256. That is a bounded output-consistency observation, **not** a native-reference or all-input numerical-equivalence test. A second hybrid run with graphs enabled gave 0.653 tokens/s and the same output as the graph-disabled hybrid run; no meaningful graph-toggle gain appeared in this case.

## Complete-answer check

A separate `gpu_layers: 47`, 128-slot request asked whether retrying an operation on the *same unavailable server* guarantees that failure risk falls from 10% to 1%. GLM explained that the failures are correlated and that multiplying probabilities requires independence. It ended normally with `finish_reason: stop`: 96 completion tokens, 34.499 s to first content, and 81.922 s HTTP wall time. The 95 visible SSE content fragments are not equated with 96 tokens because the final token emitted no visible fragment. The exact response hash and text are retained in the raw receipt and local experiment archive.

- The first combined build failed while linking the `ews-stream-unit` test target with shared libraries. The `eie-server` target then built and served Gemma and GLM. This run **does not qualify the EWS unit test target**.
- The [raw receipt](data/ews/glm53-ews-hip-x2-20261124.json) contains the nine original per-profile JSON receipts, their SHA-256 digests, the model-copy receipt, HTTP timing/usage, EWS counters and source-log hashes. Full server logs are retained in the local experiment archive but are not part of this publication. The profile labels and prompt are recorded in that receipt.

This is a feasibility and scaling observation, not a production throughput promise. It has no paired native baseline, controlled cold-cache protocol, repeated trials, long-run stability check, general quality evaluation, power measurement or simultaneous GRCA load. Windows reported roughly 29.5 GB free system memory during the 128-slot profile. GRCA was left stopped after the experiment, with its state directories retained.
