# P0.4 — Synthèse : réplication du régime fin (2026-08-16)

Diagnostic hors verdict (protocole : `P0.4-ENV.md`, figé avant traces).
Question posée : Qwen3-30B-A3B — MoE fin **sans shared expert**, load-balancing
global réputé agressif — ressemble-t-il à Gemma ou à Mixtral ?

## Réponse : profil Gemma. La thèse granularité tient au test le plus dur.

| Grandeur (F = 25 %) | Mixtral 8x7B | Gemma-4-A4B | **Qwen3-30B-A3B** |
|---|---|---|---|
| Concentration (H_stat−F)/(1−F) | 0,10 | 0,81 | **0,65 (code) / 0,81 (prose)** |
| H_static | 0,29–0,33 | 0,865 | **0,74 / 0,86** |
| H_Bélády | 0,40–0,43 | 0,924 | **0,89 / 0,92** |
| C_LRU-K (Go/token) | 5,1–5,3 | 0,11 | **0,26 / 0,18** |
| Plafond I/O LRU-K @4,5 Go/s | ~0,9 | 41 | **17 / 25 tok/s** |
| Entropie norm. par couche (médiane) | 0,985 | 0,723 | **0,798 / 0,739** |

Trois architectures, deux familles d'entraînement, un contrôle négatif :

- **Mixtral** : contrôle négatif — 8 experts généralistes équilibrés, pas de hotset.
- **Gemma-4-A4B** : positif — 128 experts fins, hotset massif.
- **Qwen3-30B-A3B** : **réplication positive sur une famille indépendante**,
  sans shared expert et sur-équilibrée. Le hotset n'est donc pas un artefact
  d'entraînement de Gemma : certains MoE fins produisent bien un working set
  physique très inférieur à leur stockage total.

Marge produit : même le pire cas Qwen (code, LRU-K, 17 tok/s de plafond I/O)
est ~8× au-dessus du plancher de 2 tok/s. Bélády à 38–51 tok/s dit qu'il reste
du potentiel dynamique (U_temporal 0,44–0,58), cohérent avec un LRU simple en
v1 et des raffinements v2.

## Leçon pour le profileur d'éligibilité (v0.4)

Le signal discriminant est l'entropie normalisée **par couche** (médiane), pas
l'agrégat : l'agrégat est ≈ 0,98 pour les trois modèles (les hotsets de couches
différentes se recouvrent sur des ids différents et aplatissent le mélange).

| Modèle | Entropie norm. agrégée | **Médiane par couche** | Verdict régime |
|---|---|---|---|
| Mixtral | 0,999 | **0,985** | inéligible |
| Gemma-4-A4B | 0,982 | **0,723** | éligible |
| Qwen3-30B-A3B | 0,976–0,986 | **0,739–0,798** | éligible |

Première calibration du pré-filtre `eie-ews-pack` : médiane par couche ≳ 0,95 ⇒
profil Mixtral, inéligible ; ≲ 0,85 ⇒ candidat, à confirmer par courbe hotset.
(Deux familles seulement : seuils à affiner, pas à graver.)

## Notes de mesure

- Débits observés (32/48 couches sur GPU) : Qwen decode 10,7 tok/s (code,
  prefill 5k) et 30,5 tok/s (prose) — A3B est rapide même partiellement offloadé.
- Le workload code montre une concentration plus faible que la prose (0,65 vs
  0,81) : la diversité du vocabulaire code active un working set plus large.
  Cohérent avec Gemma (prose seule tracée) ; à garder en tête pour les cibles
  batch NMM (mélange de régimes).
- Bigramme : 0,52–0,55 de précision, règle stall-bytes non satisfaite (sauf un
  point isolé) — confirme la rétrogradation du RoutingPredictor en v2.
- Statut : diagnostic. Le re-verdict formel reste G1–G4 sur Gemma derrière le
  gate v3 (audit GPT → go Alex → hash → traces), inchangé par ces résultats.
