# GLM consumed EWS on the laptop - 8 September 2026

Maintainer-side functional experiment, not independent replication or a speed
benchmark. This is an **actual EIE/EWS port**, distinct from the earlier
[native CPU/mmap baseline](glm53-native-next-20260908.md). The first placement
uses **host expert buffers and CPU expert computation**, with partial CUDA
offload for other weights. It is not yet GLM GPU-expert streaming.

## Artifact, runtime and placement

- Same six-shard GLM-5.3-Flash UD-Q4_K_XL artifact as the native baseline:
  revision `621d456e93e926e4b52f85cff5f634358c1828f9`, 199,707,321,347 bytes.
  All six shards were independently rehashed. No conversion or smaller model
  is substituted for this test.
- Runtime: `unslothai/llama.cpp` at
  `b9b8207fcfc2962093b9466df7af4ff29c2a81ef`, plus the published
  [GLM EWS patch](../../patches/ews-runtime-glm5next-b9b8207.patch).
  Patch SHA-256: `dfa6b873fd77afcddb2d70baa02578efe506d952f20938964f590f4a2b141ac9`.
  EIE's default Gemma runtime pin is unchanged.
- i9-14900HX, 34,070,192,128 bytes physical RAM, RTX 4090 Laptop GPU;
  Windows / MSVC 19.44 / CUDA 13.2.78 / SM89, driver 595.79.
- 42 routed trunk layers, 288 logical experts, top-8 routing, 8 physical
  slots per layer. Separate gate/up/down projections retain their actual
  Q4_K/Q5_K/Q6_K layouts. The unused MTP block is excluded.
- Eight CPU threads, 20 GPU layers, CPU expert override, F16 KV, flash attention
  off, TF32 off, CUDA graphs disabled, one-token microbatches. The numerical
  gate uses context 512; HTTP serving uses context 2048.

The routed expert tensors total **185,478,414,336 bytes**. The compact cache
contains **5,152,178,176 bytes**. The model's other weights, recurrent/KV state,
scratch buffers, driver allocations and the Next resident are additional.
**5.15 GB is not the machine's RAM requirement.**

## Actual Next loop and retained failures

The experiment imports Next's real session, turn and tool implementations,
using new empty state. The 12B has 23 exposed tools, its configured 16k context
and Nomic embedding. No original memories or documents are copied; vision and
idle drivers are disabled for this measurement. Configured 16k capacity is not
an exercised 16k prompt.

The resident first answers `6 + 7`, then chooses an actual
`request_deep_analysis` call. It asks GLM to counter-examine the assertion that
retrying a 10%-failure operation always reduces failure to 1%, including a
shared server outage. The same resident then integrates the result and answers
`21 + 34`. Its generated question is retained, not supplied by a fake backend.

- **Live attempt 1:** launcher stdout encoding failed on Windows. The owned
  EIE process was stopped; original Next state remained unchanged. This is a
  harness failure, not model success or failure.
- **Live attempt 2:** the actual tool call, resident synthesis and subsequent
  answer succeeded. However, GLM emitted 768 tokens of analysis, ending with
  `finish_reason=length`, `incomplete=true`, after 1,195.234 s. The full-answer
  gate failed and that failure is retained.
- The actual GGUF template always opens `<think>` and ignores
  `enable_thinking=false`. EIE previously returned everything that followed as
  answer text. The correction closes a still-open native reasoning prefix in
  EIE's existing answer-only mode. It is not a larger token allowance or a new
  behavioral instruction. Tests use the real vocabulary/template without
  loading weights, on both GLM and Gemma.
- **Live attempt 3: PASS for the functional gate**, with the same 768-token
  ceiling. GLM finishes normally, the resident integrates its answer, and the
  later resident turn completes. Original Next state is unchanged and all
  experiment-owned inference processes are stopped.

After cleanup, GPU usage returned to 584 MiB. The 2.83 TB figure counts repeated
reader operations over this one request, not unique weights or an SSD hardware

**Functional is not a quality score.** GLM identifies the independence/common-

table and then corrects it. The resident's final sentence has imprecise
success/failure wording. The unedited generic question, GLM answer and resident
synthesis are retained in the public data; this run does not establish frontier
quality or perfect instruction following.

## Reproduction and boundaries

The [build, configuration and HTTP recipe](../GLM_EWS_EXPERIMENT.md) is independent
of proprietary Next. It also documents the exact numerical test command.
The Next integration itself cannot be independently reproduced without Next;
private context envelopes are retained locally, not published.

Next uses its existing standalone endpoint mode (`external-unverified`), not
an EIE Job-owned attestation. The experiment separately records the EIE binary,
runtime, configuration and process it actually launched. Production Next and
the native GLM reference are not replaced.

Byte counters measure explicit reader/copy operations, not all SSD-controller
or PCIe traffic. Sampled process and whole-host memory must be read separately
from tensor sizes. No whole-system memory-saving percentage, energy saving,
multi-GPU result, MTP result, multimodal qualification, long-context guarantee
or training-GPU reduction is established here.

The earlier Next offline false-attribution failure is not resolved by an online
GLM success. GPU expert placement and a longer frozen corpus are separate next
milestones, not implied by this host-cache result.
